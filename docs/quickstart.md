# Quickstart — first run on a fresh machine

Verified end-to-end against main `02db5d25` (2026-11-23) in a clean clone with
no private workspace and no corpus checkout. Every command below was run
there; the troubleshooting section records the exact failures a fresh machine
hits and the escape hatch for each.

## 1. Install

```bash
git clone https://github.com/4444J99/organvm-engine.git
cd organvm-engine
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
organvm --help
```

There is no `requirements.txt` — install from `pyproject.toml` as above.
`pip install -e .` (without `[dev]`) is enough for the CLI alone.

## 2. Run the representative workflow

The engine's canonical data lives outside this repo (the corpus repo holds
`repo-registry.json`; a workspace holds `<org>/<repo>/seed.yaml` files), so a
fresh machine points the commands at local stand-ins. Nothing below needs a
private asset.

```bash
# Registry: validate and inspect the checked-in minimal fixture (6 repos).
organvm --registry tests/fixtures/registry-minimal.json registry validate
organvm --registry tests/fixtures/registry-minimal.json registry show organvm-engine
organvm --registry tests/fixtures/registry-minimal.json registry list --organ ORGAN-I --format json
organvm --registry tests/fixtures/registry-minimal.json governance check-deps

# Seed: build a one-repo workspace layout and validate it.
mkdir -p /tmp/organvm-quickstart/4444J99/organvm-engine
cp seed.yaml /tmp/organvm-quickstart/4444J99/organvm-engine/
ORGANVM_WORKSPACE_DIR=/tmp/organvm-quickstart organvm seed discover
ORGANVM_WORKSPACE_DIR=/tmp/organvm-quickstart organvm seed validate
ORGANVM_WORKSPACE_DIR=/tmp/organvm-quickstart organvm seed graph

# Dispatch: validate the checked-in minimal payload.
organvm dispatch validate tests/fixtures/dispatch-payload-minimal.json

# Metrics: point --registry at a COPY — the command writes
# system-metrics.json next to the registry file.
cp tests/fixtures/registry-minimal.json /tmp/registry-quickstart.json
organvm --registry /tmp/registry-quickstart.json metrics calculate

# Docs: audit this repo (it reports real findings — see below).
organvm docs audit . --format markdown
```

Expected results on a fresh machine:

- `registry validate`: `Registry Validation: 6 repos checked / All checks passed.`
- `seed validate`: `1 passed, 0 failed` (the one seed is this repo's own).
- `dispatch validate`: `PASS: tests/fixtures/dispatch-payload-minimal.json`.
- `docs audit`: two ERRORs — `missing-project-record` (this repo has no
  canonical `project-record.yml` yet) and 31 broken local links from the
  auto-generated block in `CLAUDE.md` (links to `../docs/logos/*.md`, which
  live in another repo). Both are known findings about this repo's docs, not a
  broken install.

## 3. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Registry not found at ... (default corpus location)` | No corpus checkout on this machine | Pass `--registry <path>` or set `ORGANVM_CORPUS_DIR` to the corpus repo |
| `seed validate` reports `0 passed, 0 failed` | Default workspace (`~/Workspace`) has no `<org>/<repo>/seed.yaml` layout | Set `ORGANVM_WORKSPACE_DIR` to a workspace root (see step 2) |
| `governance audit` fails with `Rules file not found` | The corpus governance rules live in the corpus repo | Set `ORGANVM_CORPUS_DIR` (the `--registry` flag does not cover the rules file) |
| Ontologia-bridge or reader-mode audit tests fail at import | `organvm-ontologia` is a private optional dependency, not on PyPI | Install it from the commit CI pins (see [CONTRIBUTING.md](../CONTRIBUTING.md)); the failures are import-only, not behavior |
| `organvm docs audit` reports broken links in `CLAUDE.md` | The auto-generated context block links to workspace docs outside this repo | Do not hand-edit inside the `ORGANVM:AUTO` markers — the block is regenerated by `organvm context sync` |

## What still needs the owner's machine

- `governance audit` and any command that reads the production registry need
  the corpus checkout (`ORGANVM_CORPUS_DIR`) — there is no public stand-in
  for the full 100+ repo registry.
- `organvm context sync` writes generated context into the workspace; run it
  with `--dry-run` first (see [README.md](../README.md#cli)).
